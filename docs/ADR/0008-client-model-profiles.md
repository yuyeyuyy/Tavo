# ADR 0008：客户端自助配置与持久模型目录

日期：2026-11-16。状态：已采用，用户确认 CLIENT_MODEL_SETUP_PLAN.md。

## 问题与选择

客户端 Key 表单依赖事先在服务端启用 profile，空目录没有输入入口，不满足用户从客户端自行选择厂商/模型的需求。选择权应在 UI，后端负责校验和持久化。

比较 API 原子改写 JSON/热加载与 SQLite 持久目录：前者代码少，但要另做文件并发/多进程刷新，容易与凭据数据库不一致；后者增加迁移/兼容导入，却可沿用现有短事务。采用后者，不另建缓存或配置守护进程。

## 决策

- 认证 API 提供固定九厂商目录与公开配置列表；创建仅接受 provider/model/label，服务端生成 ID，启用、预算和端点沿用可信预设。拒绝原始 Key、任意 baseUrl/headers/system/存储引用。总配置 32 项，用数据库写锁保证并发不超限，拿到锁后再检查会话。
- 客户端始终能从空目录添加模型；有配置时用“添加模型”展开，成功收起并聚焦 Key 密码框。模型 ID 手动填写实际 API 标识，首轮不猜最新模型列表或联系厂商发现接口。
- Alembic 0004 新增 model_profiles/model_catalog_state。初始化时在一个事务内只导入一次旧 JSON，包括空目录；保留旧 ID、目标、预算、默认标记和 Key 绑定。完成标记后不再读取 JSON 覆盖 SQLite，原文件保留。
- ChatService、ModelKeyHandler、CLI 都通过同一持久目录解析，不用只在单进程存在的可写配置副本。一次聊天捕获已验证 profile；当前不开放配置修改/删除。
- 添加普通配置与 JWE 保存 Key 分两步，分别显示未配置/已保存。没有跨请求事务或自动重试；保存响应丢失先刷新。Key 继续用已有受限提交器/CAS/SecretStore，不通过普通 JSON 设置接口传输。

## 代价与边界

本次升级先备份/停旧服务并 init 到 0004、重启一次；之后添加无需重启。新建 profile 默认端点/2048 预算，旧自定义端点仅兼容保留；界面暂不编辑/删除配置、改地区/网关或自动测试连通性。不宣称最新模型可用性或真实厂商成功。

测试只在测试 harness 的 Python 入口注入回环模型预设，生产 CLI/环境变量/Renderer 没有该入口。实际加密、认证、数据库与 Electron 流程仍走生产实现。文件和结果见 CLIENT_MODEL_SETUP_REPORT.md。
