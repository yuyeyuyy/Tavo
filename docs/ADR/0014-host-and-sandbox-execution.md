# ADR 0014：独立宿主命令与兼容沙箱路由

2026-11-17。状态：用户明确确认方案并实施。

新增sandbox和host_bash两个公开入口，复用原工具循环、Decision、Pool及Docker实现。旧bash始终保留Docker含义，不能把历史已批准脚本改在真实主机上执行。新Session持久execution_scope=host_and_sandbox并冻结策略5；0008迁移已有行设sandbox_only，原策略1–4保持。客户端无执行位置开关，三档审批同时作用于两个命令入口，其他工具不受影响。

宿主以Python后端当前用户执行。与独立OS账号/远程Runner相比，复用本地身份更符合当前本机需求且无重型部署依赖；代价是没有容器或凭据强隔离。普通容器中的后端不等于Mac。最小环境、已知敏感路径与流式/发布前凭据检查不能称为恶意脚本安全沙箱；Docker权限本身也可能带来高权限。

新增HostExecution，不滥用旧容器字段保存PID。标准库监督进程与结果FD、父管道/心跳、独立进程组提供正常进程树的生命周期管理；结果FD不传给Bash，避免伪造退出码。有效watchdog受Worker租约约束。旧PID只有在监督器执行ID/路径/组归属核对后才用于终止请求，未知占位不无条件释放；未知写入不自动重放。宿主真实文件和Docker持久服务无自动回滚承诺。

两目标共享原Run预算、审核和结构化结果，但资源边界分别描述，宿主不宣称Docker CPU/内存/PID限制。Frontend同步生成契约/Zod、六工具上限和明确的审计目标，保留六方法原生桥接与加密Key功能。

独立本机、Docker、合成模型、升级和桌面/未签名测试包验证见[实施报告](../HOST_SANDBOX_TOOLS_REPORT.md)，操作见[指南](../HOST_BASH_GUIDE.md)。
