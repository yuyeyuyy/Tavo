# ADR 0004：结构化记忆、受限上下文与只读工具

状态：已采用，2026-11-14；用户确认首轮 Mock 闭环。

选择复用 LangGraph 流程，SQLAlchemy 保存账户监控偏好与运行记录。另一方案是自写通用 Agent 循环/先引入向量检索；当前没有真实模型或大量自然语言资料，前者重复实现现有流程，后者增加依赖与隐私/检索成本，因此暂不采用。

记忆只有 monitoring.preference，账户/类型唯一，金额字符串，币种匹配、过期不选取，expectedRevision 在 BEGIN IMMEDIATE 中比较；删除保留无内容的版本墓碑，防止旧版本重新覆盖。ContextBundle 冻结来源与偏好版本，12 KiB UTF-8 上限，超限仅裁去旧辅助历史；不把字节当 token。

两个内置工具只读本地公开状态和事件摘要。工具参数没有 accountId/SQL/URL/路径，账户与租约来自 Worker 构造的 RunScope。每步调用前和结果提交前重新核对 run/owner/fence/账户；错误清理仅能在同一有效执行归属下更新审计状态。线程池最多 2 个，超时不假定硬终止底层读，未结束读取继续占用调度名额，晚到结果不落库。

AgentRunContext 与逻辑 step 唯一的 AgentToolCall 保存白名单快照/版本和执行元数据，不保存任意工具完整响应。恢复时沿用已捕获上下文，成功步骤可复用，未成功步骤增加 attempts；这不是 LangGraph 持久 checkpoint，也不承诺外部 Exactly-once。

后果：一次运行可能使用创建上下文时的偏好，用户之后修改/删除只影响新运行；历史结果和上下文仍用于解释历史行为。当前单所有者、无真实模型、无写工具、无任意插件宿主；工具注册是可信后端代码边界，不是执行第三方 Python 的沙箱。
