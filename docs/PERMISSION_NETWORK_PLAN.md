# 默认联网、三档命令权限与对话表达调整

日期：2026-11-17。状态：用户已确认三个档位仅控制Bash，以及任意公网HTTPS无请求审批，按本方案实施。实施和验证结果见 [PERMISSION_NETWORK_REPORT.md](PERMISSION_NETWORK_REPORT.md)。

## 当前差距

- 默认network.mode=none，目标列表为空；出口只接受预配置别名，因此只改proxy开关不会实现默认访问公网。
- 所有外部写方法先进入APPROVAL_REQUIRED，内部http_request经Decision人工执行；无审批需要改代理和Agent循环，不能伪造用户批准记录。
- 客户端旧模式为auto_readonly/ask/disabled/auto_sandbox，影响所有注册工具；用户本轮表达可能指“完全访问权限/帮我审批/请求审批”三个新档位，需要明确。
- 普通脚本仍在非root禁网容器中，经UDS代理提交应用级请求；资源和宿主边界由实际容器实现，不依赖模型文本。
- 对话模型系统提示明确提及工具/账户能力，Mock有说明工具清单的回答；缺少统一的“正常回复不主动暴露内部工具名”规范。

## 已确认范围

1. 新客户端三个档位：**完全访问权限、帮我审批、请求审批**，只控制Bash命令；新会话默认完全访问。完全访问指沙箱工作区和公网操作，不指宿主Mac/root/Docker Engine。其他工具免额外命令审批，但保留认证、参数、归属、资源与网络地址边界。
2. 默认可以访问任意公网HTTPS域名，不需要逐域名配置；所有HTTP写方法不再进行独立请求审批。仍经受控代理，宿主/内网/元数据与凭据边界保留。若用户选择“只允许配置域名”，则保留域名列表约束，仅取消请求审批。
3. “不透露工具”针对正常回复正文：不主动罗列工具名、函数名、内部调用流程、沙箱实现。表达任务进展、结论与必要的失败原因，如实说明未完成，不声称成功，不假称无执行能力。独立的审计/操作记录继续保留；若用户要隐藏UI记录，需要另行明确。

## 最小增量方案

### 命令权限

| 档位 | Bash行为 | 其他工具 |
| --- | --- | --- |
| 完全访问权限（推荐默认） | 在沙箱既定权限内免人工/模型审批；大范围工作区版本提交也按此档位自动进行 | 自动执行合法调用，免额外审批 |
| 帮我审批 | 后端基础校验后由现有独立模型审核批准或拒绝；意图不明确可向用户请求确认 | 不套用Bash审批档位 |
| 请求审批 | 每个合法Bash调用请求用户明确批准；版本提交绑定相应摘要，必要时批准具体diff | 不套用Bash审批档位 |

复用现有Decision/ToolCall/ToolResult，不能把“自动执行”记录成human批准。取消/结果未知、租约/fence、参数摘要、重复执行和资源名额仍由后端维护。工具免审批不代表新增任意工具、宿主权限或无上限循环。

新策略版本冻结在Context中，旧策略1/2/3、旧会话和等待中的批准不重新解释或扩大权限。新UI切换档位沿用“开始新会话”行为，旧模式只作历史兼容显示/API读取。ReviewMode增加新合法值，Pydantic/OpenAPI/生成TS/Zod同步；现有数据库字段是String，若最终无结构变化则不新增迁移。

### 默认公网与无请求审批

沿用UDS出口代理而不是给执行容器普通bridge直连。两种实现取舍：普通bridge容易让requests/curl联网，但没有现有SSRF、Token和目标验证边界；代理默认允许公网增加URL目标能力，继续复用已验证的解析/连接/配额机制，改动和边界更可控，推荐后者。

- 默认proxy，新增管理员控制的公网范围/写方法审批配置；默认允许的范围按上述用户选择确定，保留none/域名列表用于管理员收紧。
- 为tavo_http增加明确的公网URL请求入口，不要求任意公开文档/API都先建别名。只接受HTTPS、标准端口、严格URL/地址校验；内部、loopback、云元数据、保留地址、用户指定DNS、CONNECT/隧道仍不允许。
- 无请求审批的新策略直接执行合法HTTP写请求，不创建waiting_review/human决定。请求仍需记录结果和错误；未知外部结果不自动重发。旧策略冻结的敏感请求继续按旧授权处理。
- 任意公网请求不携带已保存Token；带凭据仍只能使用预先绑定的目标/方法/路径，不把模型Key、已有API Token广播给任意域名。重定向逐跳检查，跨源不带认证，同源不扩大凭据绑定路径。
- 普通requests/curl依旧没有透明直连能力；默认“可以上网”指Agent具备受控公网请求能力。如用户实际要求任意程序直接联网，需要另行确定该部署边界，不能将代理称为透明全网。
- 依赖来源/哈希、资源上限、限流、请求/响应大小继续配置管理；本轮“工具不做限制”仅解释为免额外审批，不默认开放任意供应链代码安装或无限内存/执行时间。

### 正文表达

复用四种模型协议共享系统提示，同时调整兼容文本聊天入口与Mock，要求直接完成用户任务，不主动解释可用工具名称/内部框架。保留向模型发送真实工具schema，这是正常调用所需；不对正文做粗暴字符串删除，以免破坏用户代码、文档或真实错误。

不隐藏失败、费用或外部副作用，也不保证提示词能做到模型绝对不泄漏；自动测试验证提示跨协议生效及Mock的可控输出，真实厂商对齐质量不靠本地替身冒充。

## 验证计划

- 三档Bash：全访问无额外等待；代审调用独立审核；请求审批阻止执行直到批准；无法绕过宿主/资源边界，自动决定不伪装human。
- 非Bash工具在新三档下均免命令审批，参数/归属/权限错误仍拒绝；取消/失租/未知结果和工具预算保持。
- 默认公网URL访问及POST/PUT/PATCH/DELETE不生成请求审批；使用合成HTTP上游测试外部写方法，不动用户第三方数据或真实付费Key。
- 真实公共HTTPS只读实连；内网/元数据/Fake-IP/DNS重绑定/重定向/跨源认证/未绑定Token仍拒绝。代理失效禁止直接网络降级。
- 旧Context、旧等待批准、现有模型/API凭据及历史会话不自动升级；契约生成与Zod兼容测试。
- 四协议提示、普通文本入口和Mock不主动输出内部工具清单；不把执行失败伪装成完成。
- lint/typecheck/test/build、独立backend/model/Bash smoke；网络真实容器和三档UI/E2E/包内相关回归，更新指南/架构/ADR/学习和评测。
