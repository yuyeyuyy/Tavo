# 客户端浅色、Markdown与聊天界面调整方案

日期：2026-11-17。状态：用户已确认推荐方案，现已实施；实际验证与边界见 CHAT_APPEARANCE_MARKDOWN_REPORT.md。以下保留设计与取舍。

## 当前差距

- styles.css把暗色背景、正文、表单、弹窗、代码及审核面板颜色写死，单改body不能得到完整浅色模式。
- Chat.MessageList直接输出字符串，助手回复中的Markdown仍以字面字符显示；用户消息的纯文本行为则应保留。
- Composer目前是多行大卡片，内含模型/权限选择和工具栏，下方还有快捷键、持久化和运行说明；与简洁聊天输入条不符。
- 模型/权限选择状态属于Chat，切换时重置展示并开始新会话；ConnectionSettings目前只负责连接、模型配置和加密Key。移动选择器必须复用这些状态/行为，不能改成互不同步的第二份设置。
- 消息采用右侧用户气泡、左侧大段助手正文/模型标签，间距和空态偏问答面板；工具审核仍须可见，不能随简化界面一起隐藏。
- Main当前拒绝所有新窗口和页面导航。Markdown若直接添加普通链接，会出现点击无效；安全外链打开需做很小的Main改动，原六方法桥接和CSP保持。

## 推荐界面

| 区域 | 调整 |
| --- | --- |
| 顶部 | 保留Tavo、会话、新对话、连接状态与设置；Mock保持明确标记，不再每条回复重复大标题/模型徽章 |
| 对话区 | 用户气泡靠右，助手气泡靠左，类似Telegram的连续聊天，保留Grok的简洁留白；小头像/身份标识，不照搬第三方品牌 |
| 输入区 | 所有空态/聊天状态都使用底部同一条圆角输入条，只有文本输入与发送/停止按钮；单行起步、长文本适度增高，保留Shift+Enter和输入法行为 |
| 设置 | 增加外观、当前对话模型、命令权限；保留连接、添加模型与Key加密提交，优先让常用设置可见 |
| 状态与审核 | 收起的工具记录仍可展开，待批准操作必须自动展开且按钮可达；宿主/沙箱目标与具体操作摘要保留 |
| 提示文字 | 移除输入条下方快捷键小字、底部持久化脚注；运行环境/连接说明收进设置，真实错误/等待批准状态仍正常显示 |

视觉采用浅色白/浅灰底与克制的用户气泡强调色；深色保留。两种主题都有清晰的正文、焦点、禁用、错误、代码和表格对比。空态只保留简短欢迎与少量示例，输入条固定在底部。

## 主题：跟随系统／浅色／深色

默认跟随系统，设置可显式选择浅色或深色。主题是客户端公共偏好，仅本地保存，不进入会话内容、模型或后端配置。使用统一CSS语义变量覆盖聊天、设置、Key表单、列表、工具卡、Markdown和滚动条。

入口尽早应用已保存主题，跟随系统时监听matchMedia变化并在卸载时清理。非法存储值、存储不可用均回退为可用状态；手动主题不被系统变化覆盖。主题切换不重置对话、不改变模型、权限或后端。

## Markdown方案与取舍

两种方案：

1. **React AST渲染组件（推荐）**：react-markdown配合remark-gfm，复用成熟解析与React安全渲染，支持段落、标题、粗体、列表、引用、链接、行内/围栏代码和常用GFM表格/删除线/任务列表。新增两个直接依赖，与版本锁一起维护；其余UI/状态继续复用现有React/CSS/Zustand。
2. **轻量解析器转HTML或自行处理语法**：前者需要额外的可靠HTML清洗与Electron安全维护，后者容易漏掉嵌套/转义/代码边界，不适合为减少依赖自行重造Markdown解析器。

选择1。官方依据：[react-markdown](https://github.com/remarkjs/react-markdown)与[remark-gfm](https://github.com/remarkjs/remark-gfm)。已核对并固定react-markdown 10.1.0、remark-gfm 4.0.1，更新pnpm锁文件；后端输出格式不变。

实现为独立MarkdownMessage组件，仅处理助手正常回复；用户输入、错误、工具原始参数/输出继续按文本显示。后端保存和发送的原始消息字符串完全不变；正常纯文本也能显示。代码块与宽表格局部横向滚动，避免把气泡或窗口撑宽；段落保留聊天换行。解析组件按内容复用，避免轮询反复解析未变化的长消息。

安全边界：skipHtml明确开启，不使用dangerouslySetInnerHTML/rehype-raw，不执行脚本、代码、数学或图表扩展。任务列表只读；表格对齐用CSS类，不为Markdown放宽生产CSP。远程图片不自动加载，显示替代文本与可点击地址，避免回复一出现就向第三方发请求。

外链只接受规范HTTP/HTTPS URL，拒绝javascript/data/file/command/tavo等协议、控制字符和URL用户名/密码。在Renderer及Main两层校验；仅用户点击后交系统浏览器，Main始终拒绝创建Electron子窗口，页面导航仍禁止。无需新增IPC方法、Node权限或网络CSP放行。代码可通过系统文本选择复制，不为本轮增加剪贴板权限。

## 设置与对话状态

ConnectionSettings扩展为通用“设置”弹窗，复用现有连接/Key组件；通过props组合当前模型和权限选择器，Chat继续持有原状态和changeModel/changeReview行为。保留“切换会开始新对话”说明；主题变更独立，不重置会话。

模型目录不可用/Key未就绪时仍禁用相应模型，旧会话的旧权限兼容显示保留。只打开/关闭设置不会改变选择，Escape关闭并归还焦点，Key表单关闭清空的行为不变。切换模型/权限与旧Run的处理沿用现有语义，不擅自取消后台任务或扩大权限。

保留历史列表、停止、重试、加载历史、离线Mock标记、输入长度限制与错误反馈。输入焦点不抢出正在打开的设置弹窗；阅读历史时不强制滚回底部，新增回复时按原跟随滚动行为更新。

## 影响范围

- renderer/chat/Chat.tsx、styles.css、connection.tsx、src.tsx：聊天布局、单条输入、设置组合与主题入口。
- 新增客户端主题模块、MarkdownMessage及纯URL校验模块；Main仅增加受控外链处理，仍保持六方法和窗口隔离。
- apps/desktop/package.json、pnpm-lock.yaml：必要的Markdown直接依赖及完整锁定。
- tests与dev/e2e脚本：模型/权限从设置中选择，新增主题、Markdown及链接安全用例。
- docs/ARCHITECTURE.md、ADR、LEARNING_LOG.md、EVALUATION.md和实施报告：界面/信任边界及实际结果。

不改Python业务、AgentPool、模型网关、工具权限、消息DTO/数据库结构；无迁移，不编辑用户数据或Key。不推送或发布。保留全部以前任务的工作区改动。

## 验证计划

- 主题：跟随系统、手动浅/深、重启保持、系统变化、非法/不可用存储；聊天/设置/Key/工具审核均正确换色。
- Markdown：标题/粗体/嵌套列表/引用/代码/表格/删除线/任务列表、中文/换行/长内容/不完整围栏；普通文本和用户HTML样例仍正确。
- 安全：HTML/script/事件属性不执行，无自动远程图片请求；恶意协议/URL拒绝，合法外链仅用户点击时交系统浏览器，无新Electron窗口；不放松CSP和原生隔离。
- 设置：选择器只在设置中，修改后新会话与实际请求一致，主题不影响会话，模型不可用状态正确；Key提交/清空/关闭/焦点、旧会话恢复和三档审批继续通过。
- 输入/布局：空态和已有对话同一底部长条、无下方小字；Enter/Shift+Enter/IME、多行与长度限制、停止/重试、滚动与窄窗口可用；待批准卡片不可被新样式隐藏。
- 复用Vitest和Playwright，执行pnpm lint/typecheck/test/build、test:dev、完整桌面E2E；Main外链修改后构建未签名ARM64测试包并运行包内回归。全部使用临时数据/合成模型/凭据，不调用真实付费模型。
- 对浅/深色、欢迎/长对话/Markdown/设置/审批和窄窗口截图做视觉复核；编译通过不称为业务或跨平台验收。

小练习：解释为什么“后端仍保存Markdown原文”与“客户端用React节点展示Markdown”可以同时成立，以及主题偏好为什么不应存到消息或影响命令权限。
