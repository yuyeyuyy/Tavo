# 沙箱工具与真实宿主机 Bash 增量方案

日期：2026-11-17。状态：用户已明确确认完整方案并实施；实际文件、验证与边界见HOST_SANDBOX_TOOLS_REPORT.md。没有执行真实项目部署。

## 当前实现与差距

- `agent/tools.py` 的 bash 只有 Docker 实现；参数cwd只能为工作区相对路径，结果使用sandboxId。
- `bash_policy.py` 把Docker、宿主目录等视为越界；三档逻辑仅识别bash，其他工具在策略4下免额外审批。新增宿主入口时必须让两种命令共同进入三档审核，不能落入“普通工具自动放行”分支。
- `assistant.py`、`context.py`、`self_review.py`、共享模型提示、Scheduler恢复和Pool资源占位均假设命令在容器中；只改工具名称会使审核、恢复与预算不一致。
- 原BashExecution记录的是容器，不适合复用container_name保存宿主PID。Session没有持久的宿主能力边界；直接更新Registry会给旧会话扩大权限。
- 客户端Context Zod最多5个工具，当前提示“命令真实执行于隔离工作区”；加入宿主入口后须同步契约和审计显示，不能继续把全部命令称为隔离执行。

## 两种可行路径与选择

1. **后端当前用户运行本机Bash（本轮推荐）**：使用现有Python标准库进程能力，能直接查询系统、进程、日志及管理该用户可访问的Docker/项目。无需新守护服务或OS账号，符合当前本地部署。代价是没有容器级宿主与凭据隔离，错误命令可能真实修改本机。
2. **单独OS账号/远程Runner**：可以通过OS文件权限和独立服务限制部分资源，但需要系统部署、鉴权与Docker权限代理。原始Docker Engine权限本身可能带来高权限，不能把“换个账号”当作完整隔离。本轮不扩展为这套部署体系。

采用方案1。这里“宿主机”明确指**运行Python后端/Worker的机器、当前用户身份**。本地启动是Mac；后端若在普通容器中运行，看到的是该容器，不会声称能自动操作Mac。要管理真实Mac须原生启动后端。本轮以macOS/Linux为执行支持范围，其他平台明确报告不可用。

## 工具与路由

| 新工具标识 / 显示名称 | 用途与实现 |
| --- | --- |
| sandbox / 沙箱 | 复用现有BashRunner、SandboxManager、Docker、版本化Session工作卷和受控出口；脚本、数据处理、临时文件、网页抓取优先选它 |
| host_bash / 宿主机 Bash | 新HostBashRunner执行真实本机命令；系统状态、进程、日志、Docker管理、实际项目部署选它 |

使用两个明确且互不复用的标识，避免把旧bash历史调用重新解释成宿主命令。原bash作为**旧策略的Docker兼容标识**保留，不向新策略重复声明。workspace_write继续只写沙箱工作区，http_request继续只负责原出口协议；时间、计算、模型配置和加密Key功能不改变。

两个入口默认同时提供给新会话，客户端没有“开启宿主机”或“选择执行位置”开关。Agent从任务及工具schema选择；模型提示说明职责、路径和真实能力，不能因沙箱失败就把宿主机当作绕过沙箱边界的默认重试通道。正常正文继续只描述任务与结果，不主动罗列工具。

## 相同的三档权限

| 当前档位 | 沙箱命令与宿主机命令共同遵循 |
| --- | --- |
| full_access 完全访问权限（新会话默认） | 合法调用自动执行，不额外请求模型或人工审批 |
| auto_review 帮我审批 | 每条命令独立模型复核，可允许、拒绝或询问用户；后端校验仍然有效 |
| request_approval 请求审批 | 每条命令先持久等待具体调用批准，绑定工具、目标、规范参数摘要；沙箱大范围提交仍绑定具体diff |

“同档位”指相同的审批流程，不声称两种环境权限相等。沙箱继续拒绝宿主路径、Engine和私网直连；宿主入口允许其任务需要的本机系统/项目/Docker访问，使用宿主实际网络与OS权限，不继承容器的内存、PID或出口隔离。宿主全访问不自动增加sudo、不处理管理员口令、不绕过OS权限；权限不足返回真实失败。

本轮新增能力属于用户明确要求的宿主操作授权；实现和测试不据此实际部署项目、删除用户文件、停止用户服务或修改远程数据。Agent实际运行仍须围绕用户的具体目标。

## 宿主执行与资源

- 独立HostBashArguments：command、cwd、timeoutSeconds；cwd可为真实绝对项目目录，省略时使用配置的默认目录。严格拒绝NUL/空命令、非法类型、无效目录和命令超长，不借用沙箱resourceProfile假称宿主有相同cgroup配额。
- 统一配置中的host段维护启用状态、默认cwd、命令UTF-8字节上限、60/300秒超时、捕获/公开输出上限、单并发、退出宽限和监督间隔。默认开启，管理员可关闭；不添加用户开关。沙箱现有资源配置不变。
- `/bin/bash --noprofile --norc`以argv启动，不执行登录脚本；不继承完整后端环境，不向子进程注入API Key、认证材料、密钥环或SecretStore。只传运行所需白名单环境；自定义部署凭据不自动授权。
- 标准库异步子进程、有界stdout/stderr和超时取消，独立进程组。使用小型受监督启动进程持有父进程管道/心跳，父进程退出或租约失效时终止所属进程组；退出先TERM再KILL并等待回收。普通后台子进程不能在命令结束后失控运行，部署持久服务应交给Docker/系统服务管理器。
- 宿主并发名额纳入AgentPool；执行意图、当前owner/fence、启动身份与完成状态持久化。重复执行、超时、取消、失租、启动失败及结果未知分别处理；无法证明结束时保留占位或明确标记需要恢复，不能悄悄当成功。
- 恢复绝不只凭旧PID杀进程，也不自动重放结果未知的部署/写命令。守护与归属验证保护自身创建的进程；显式脱离进程组、交给外部daemon的效果不能假称已撤销。
- 结果沿用success/exitCode/stdout/stderr/errorCode/errorMessage/durationMs/timedOut/truncated，并增加明确executionTarget/executionId；host的sandboxId为空，旧结果兼容读取。

### 凭据和安全的实际边界

保留项目P0：不主动读取Tavo密钥环/认证/凭据、不把原始Key放入模型、Renderer、普通日志或测试快照。实施最小环境、已知敏感路径规则、输出进入Repository/LLM前的凭据检测/脱敏与拒绝，不记录原始敏感输出；测试仅用合成敏感值验证。

**这不是宿主文件系统沙箱。** 任意本机代码以同一OS用户运行时，路径黑名单、模型审核、环境清理和输出脱敏不能提供针对恶意脚本的强隔离；可通过脚本、子进程或Docker权限间接接触该用户能访问的资源。若需要“任意恶意命令也绝不能读到本机凭据”的保证，必须采用方案2并专门限制Docker权限，不能把本轮方案1描述成具备这种保证。宿主默认开启意味着信任本地Owner发起的任务和模型执行流程，不适合不可信多用户服务。

## 兼容、迁移与接口

- 新Context策略5冻结执行目标与host配置。0008新revision为Session持久保存executionScope：迁移已有行设sandbox_only，新三档创建的新会话默认host_and_sandbox；旧模式默认保持sandbox_only。客户端不提供切换该字段的入口。
- 旧Session、冻结策略1–4、待批准调用和旧bash历史继续Docker语义，不自动获取宿主权限；新建会话才能获得双入口。升级不修改0001–0007、原始消息、模型配置、凭据或工作卷。
- HostExecution新表保存宿主执行状态/占位和租约归属；复用ToolCall/ToolResult/Decision，而不是另造聊天或队列系统。
- ToolRegistry、ContextBuilder、分类/模型审核、Assistant路由、预算、Scheduler恢复和Services生命周期一致支持两种执行目标；模型历史保留旧标识，系统提示说明历史bash是Docker，避免误用宿主cwd。
- /agent-runtime增加独立宿主状态；原bash状态字段保留Docker含义，新工具列表最多6项。Pydantic/OpenAPI生成TS与Zod同步；客户端审计显示执行目标、cwd及批准详情，替换“所有命令均隔离执行”的提示，保留三个权限选项和六方法原生桥接。
- Docker启动检查/构建/预热保持原行为。宿主能力不自动取消现有Docker启动前置；管理员显式关闭沙箱时，宿主入口仍可独立工作，不要求Docker存在。

## 验证计划

- 新会话默认双入口，旧会话/冻结Context/待批准Docker命令不升级；0001–0007不变、0008升级保留旧数据/Key。
- 两目标×三档：自动执行、模型允许/拒绝/询问、人工批准/拒绝/过期、参数摘要不可改；宿主入口不能走“其他工具免审批”分支。
- 宿主普通命令、临时测试项目写读、退出码、cwd/空参数/超长/超时边界、环境剔除、合成凭据输出拒绝/脱敏；无生产路径写入。
- 主进程/子进程取消与回收、Worker退出、失租、未知结果不重放、PID身份不符不误杀、容量不超限、两种工具都计入Run预算与重复失败上限。
- 沙箱Docker脚本/文件/抓网页/DoH/凭据/私网和宿主隔离回归；host检测系统状态、进程和Docker只读状态。部署仅在临时项目用替身脚本验证，不部署真实项目或写真实远程服务。
- 四协议合成模型能选择正确目标并完成失败修复；正文不主动透露工具，审计目标真实。没有真实付费模型请求。
- api:generate、lint、typecheck、test、build、独立backend/Bash烟雾；真实宿主与Docker集成，客户端开发/E2E与未签名测试包。明确区分当前平台实际运行、替身和未覆盖平台。
