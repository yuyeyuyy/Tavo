# 客户端改为单页对话的设计（已确认方案 A）

日期：2026-11-14。需求：客户端整体改成类似 Grok 的对话形式，先完成交互界面。用户已确认“按方案 A 开始（推荐）”；实施结果见 CHAT_CLIENT_REPORT.md。

## 推荐结果

单页、深色、低饱和、以输入为中心，使用 Tavo 自己的名称和图标。移除总览、账户连接、活动记录、Agent、设置五项业务导航和原仪表盘布局。界面只有对话，以及顶部小型连接设置入口。

```text
┌──────────────────────────────────────────────────────────┐
│ Tavo                         新对话   连接状态   设置图标 │
│                                                          │
│                    今天想聊点什么？                      │
│                                                          │
│         ┌──────────────────────────────────────┐         │
│         │ 输入消息…                            │         │
│         │                           Mock  [↑]  │         │
│         └──────────────────────────────────────┘         │
│            [认识 Tavo] [了解记忆] [了解工具]             │
│                                                          │
│              首次发送后切换为消息列表                     │
│              输入区固定在对话底部                         │
└──────────────────────────────────────────────────────────┘
```

空态欢迎标题与输入框居中；有消息后显示居中限宽的用户/助手消息流，底部为多行输入框。用户消息用轻量背景，助手文字直接排版；使用克制的间距、边框和动效。宽窗口不拉满文字，窄窗口保持输入框和操作可用。

首轮只做单一会话与“新对话”，不先加入会话侧栏、搜索、上传、联网、模型选择器或原业务功能的自然语言替代。设置以弹窗承载后端地址、连接/重连和必要状态，不再作为业务页面。

## 两种可行范围

| 方案 | 能交付什么 | 代价与边界 |
| --- | --- | --- |
| A：先完成对话客户端（推荐） | 完整布局、发送、停止、失败/重试、新对话、示例提示；可替换的 Mock 消息适配器 | 当前没有真实聊天模型，消息仅本次客户端运行内保存，重启不保留 |
| B：同时增加真实聊天后端 | 在 A 上增加服务端 conversation/message、模型适配和流式响应 | 需另行确认模型/密钥/费用/数据传输、会话持久化与恢复协议，范围明显超过此次“形式先” |

推荐 A。当前后端 `/agent/analyze` 只接收 eventId 并分析持久事件，不能把任意用户消息塞进它当作聊天。已有 Agent 记忆、上下文、工具和队列保留在 Python 后端，后续通过正式聊天接口衔接。

Mock 回应明确标注为界面演示，只覆盖示例说明/通用演示回复，不假装运行账户查询或真实工具，不使用假模型名称。后端未连接时仍可体验本地对话界面，连接状态如实展示。不会安装新依赖或请求外部模型。

## 交互和接口

- 文本框自动增高，Enter 发送、Shift+Enter 换行，中文输入法组词期间的 Enter 不触发发送；拒绝纯空白，单消息最多 4000 字符。
- 同时只允许一个回应，发送中按钮切为停止；新对话会中止当前回应并清空当前会话，不删除后端账户/事件/分析。
- 消息区有加载、错误和重试状态，键盘可操作，设置弹窗支持关闭/Escape 与焦点返回。滚动时尊重正在查看旧消息的用户，不持续抢到底部。
- `ChatMessage` 只包含客户端 messageId、role、文本、时间和状态；`ChatTransport.reply(messages, signal)` 负责获得回应。首轮注入 MockTransport，后续用 HTTP/流式实现替换，组件不直接编排工具。
- 对话状态是客户端交互数据，与服务端 AgentMemory 不同；本轮不写 localStorage/数据库，不把聊天消息自动作为长期记忆。
- 消息以 React 纯文本显示，不使用不受控 HTML。Renderer 不接触凭据，沿用原生 6 方法和现有受限 HTTP/配置能力。
