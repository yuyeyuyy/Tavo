# 模型单次输出耗尽与最多三次重试方案

日期：2026-11-17。状态：用户要求自动重新发送、最多重试三次，并授权使用合成内容自查链路；用户已确认完整方案并实施；实际结果见 MODEL_RETRY_OUTPUT_REPORT.md。原失败对话不得重发。

## 已确认的根因

真实官方 API 合成对照已复现：当前 2048 单次生成上限全部用于思考，finish_reason=length、无正文、无 refusal，HTTP 200；仅关闭思考便能生成正文。同一条件通过实际 ModelGateway（trust_env=false）也得到 MODEL_REJECTED。错误位于请求参数/响应分类，而非账户余额不足。原失败响应未保存，不能假装已经恢复那一份原文。证据见 [诊断记录](DEEPSEEK_RESPONSE_DIAGNOSIS.md)。

当前 reply/turn 分别实现 HTTP/解析，且无重试；ModelProfile/SQLite 配置上限为 8192。Assistant 外层有单次模型调用 60 秒、审核 30 秒及 Run 总时间限制，ChatService 也有 60 秒与断线取消。工具执行和模型调用是不同步骤，未知模型请求在重启后不会自动重放。

## 取舍与推荐

方案 A：显式关闭思考，保留现有 2048 上限。改动小、响应快，但改变模型推理能力，仍不能解决网络抖动与准确报错。方案 B：保留思考，识别输出预算耗尽并在有界重试中增加预算，同时细分错误和记录安全元数据。推荐 B；本方案采用 B，不暗中关闭思考或切换厂商。

## 行为与边界

1. 每个逻辑模型请求最多**重试 3 次，即初次 + 3 次，共至多 4 次 HTTP 尝试**。包括文本回复、Agent 的一轮模型调用及独立模型审核；各自仍受现有外层超时/Run 总预算限制，取消、断线或预算先到便立即停止，不承诺一定用满四次。
2. 对已官方确认的 DeepSeek 新模型，仅当正常 HTTP 响应因 length 且没有正文/完整工具调用时，按本次尝试预算翻倍，最大 16384。当前 2048 配置对应 2048 → 4096 → 8192 → 16384。思考模式明确保留，不把 reasoning_content 显示成正文。
3. 将重试的执行上限与数据库中的初始模型预算分开：不改已有 profile、SQLite CHECK、旧 Context 或新建默认值。预算覆盖值仅由后端重试策略传入请求构造器，不能从客户端/工具参数传入。其他厂商不套用 DeepSeek 专属参数或更大预算；超过策略上限不继续增加。
4. 连接抖动、请求超时、明确可恢复的 429/5xx/上游生成中断，以及正常响应中的空回复可受控重试。401/403、余额不足、无效模型/参数、404、明确拒绝/内容过滤、非法响应/敏感数据校验失败不盲目重试。截断的工具参数继续拒绝，不执行或猜测补全。
5. 常规重试采用短异步退避；合法 Retry-After 在剩余预算内遵守，过长则停止。不能越过外层模型/审核/Run 时间限制，不使用阻塞 sleep，不创建脱离取消控制的后台请求。
6. 重试只重发同一轮模型请求，不再次写 UserMessage、不新增逻辑轮次、不重新执行已有工具。RunScope/lease/fence 和工具预算仍生效；Worker 重启遇到未知在途请求仍按原语义中断，不偷偷重新付费请求。用户本次明确授权的自动重试覆盖以前默认不自动重试的规则。
7. 正常有正文的 length 响应仍按截断成功展示；正常无正文但完整 tool_calls 的响应仍交原审核与执行流程。重试不改变工具权限、审批或宿主/沙箱隔离。

## 最小接口与配置

- 新增小型 ModelRetryPolicy，由 Settings/服务注入 ModelGateway。统一配置最大重试次数（默认3、允许0–3）、DeepSeek重试生成上限（默认16384、明确有界）、异步退避；不把模型配置塞进 Bash 策略，不引入第三方依赖。
- ModelGateway 复用一个内部请求/解析尝试函数，reply/turn 使用同一重试控制；request_for/turn_request 接受仅后端传入的每次生成预算覆盖。构造参数和 DTO 默认行为保持兼容。
- 增加 MODEL_OUTPUT_LIMIT 与 MODEL_EMPTY_RESPONSE，保留 MODEL_REJECTED 用于明确拒绝，保持 MODEL_RESPONSE_INVALID 的安全校验。更新 Python/共享TS错误定义、OpenAPI生成类型及客户端Zod，使最终失败能清楚显示。
- 每次尝试只记录白名单诊断：独立诊断关联标记、阶段（构造/传输/读取/解析/重试）、厂商/协议、次数、HTTP状态、允许的结束原因、输出上限、计数/耗时、正文/思考是否存在、是否继续。不得记录Key、请求/响应正文、私有思考、凭据/会话标识、上游原始异常或任意error.message。
- 本轮不增加数据库迁移或新的UI设置/重试进度组件。日志与确定性测试足以定位当前链路；持久调用审计可后续独立设计。

## 影响范围

后端 llm/adapter.py、turns.py、新重试纯策略模块、core/config.py/errors.py、服务装配；共享错误与生成契约；相关模型/Agent测试、模型烟雾/桌面错误场景夹具；.env.example、模型说明与本轮文档。不修改工具执行器、会话业务、历史数据或Key存储。

## 验证计划

- 现有 ModelGateway 可注入 MockTransport/时钟/异步等待，所有日常自动化使用合成数据：验证尝试次数最多4、0重试、指数预算/封顶、空回复、普通截断成功、明确拒绝/鉴权/参数/余额错误不重试、临时故障后成功/耗尽、Retry-After、计数与脱敏。
- 验证文本回复、Agent轮次与审核调用共享规则；工具调用不重放，用户消息/模型轮次不重复写入；取消、断线、30/60秒及Run预算、租约丢失和未知在途恢复仍有效。包含截断/重复/非法工具调用边界。
- 更新受重试影响的现有烟雾与E2E替身：短暂故障改为恢复，持续故障才显示最终错误；不通过加等待掩盖重试/取消问题。
- 实际运行 api:generate、lint、typecheck、相关测试与全量普通测试、build、backend/model smoke；错误协议涉及客户端时运行开发/桌面及未签名测试包回归。
- 用户已允许自查实际链路：完成后使用固定合成输入、最多两次真实官方逻辑调用验证重试/成功或精确耗尽，单逻辑调用仍至多4次、单次输出至多16384；只记录安全指标，不发送用户对话、不执行工具。合成/真实验证分别记录，真实失败不得宣称已通过。
